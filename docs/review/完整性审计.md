# 数据完整性审计（结构化是否"完全没问题"）

「完全没问题」得先有判据，否则无法证明。这里把它拆成 4 个机械维度 + 1 个人工维度：

| 维度 | 判据 | 工具 | 现状 |
| --- | --- | --- | --- |
| ① 数字覆盖 | 原文里每个数字，必须被 `value`/`perValue`/`cap`/`min`/`threshold`/`level`/`addition` 之一承载 | `node docs/review/tools/coverage.mjs` | 2 条不承载，均为非语义数字（见下） |
| ② 片段覆盖 | 按「，；」切开的每段话，必须被 `effect.text` 或 `condition.text` 覆盖 | 同上 | 28 条候选，逐条判过：全部由类型字段承载（见下） |
| ③ 标记覆盖 | `<$cc.g.*>`/`<$cc.tag.*>`/`<$cc.bd*>`/`<$cc.tra.*>`/`<$cc.t.*>`/`<$cc.c.*>` 是否能落到结构化字段 | 同上 | 候选 50 条，均为"概念型标记"或已由 target/stacking 表达 |
| ④ 字段自洽 | `per` 缺 `perValue`、有「最多 N」缺 `cap`、有「每 N 单位」缺 `per` | 同上 | 0 |
| ⑤ 语义正确 | 数值方向、条件归属、计数口径是否符合中文原文 | 人工逐条读（reviewer 团队） | 见审核报告 `核对-*.md` |

## ② 片段未覆盖（28 条，逐条判过：全部已由类型字段承载）

典型几类，均可解释：

| 片段类型 | 例子 | 承载字段 |
| --- | --- | --- |
| 分母从句被删成计数域 | 「宿舍内每有1名干员」 | `countScope.room` |
| 计数范围限定 | 「基建内（不包含副手及活动室使用者）每有1名X干员（最多N名）」 | `per`/`perValue`/`cap`/`excludeAssist` |

| 装备/标签主体 | 「控制中枢内每有1名彩虹小队干员」 | `per`+`factionId` |

若要彻底消除这类"文本未覆盖"告警，可让 `text` 保留整条原文片段；当前选择是 `countScope`/`per` 等字段优先，`text` 只存效果主体。

## 仍然只能算「已知缺陷」的部分（不是解析器能解决的）

1. 副手、活动室（`PRIVATE`）未建模 → `excludeAssist` 只是标志位。
2. 特殊资源链（感知信息→思维链环、人间烟火→巫术结晶…）只有 `resourceId`/`sourceResourceId`，没有产出-消耗模型。
3. 概率类（`clueBias`、`orderQuality`、`byproductGuarantee`）只有 `level`/语义，算不出期望值。
4. 分支名只有中文，`subProfessionId` 对照表缺（决策 4 遗留）。
5. ~~`capacityBelow(16)` 边界口径未定~~ → 已定：`capacityBelow` 含 N（`op: "lte"`）。
6. 「部分设施」「特殊加成（与部分技能有特殊叠加规则）」原文无数值、无枚举 → 只落 `specialBonus` 占位（歌蕾蒂娅、玛恩纳 3 条）。

这些**不是数据缺字段**，是"模型没定义"，需要先定口径再谈结构化。

## 怎么用

```
node docs/review/tools/coverage.mjs                    # 四个维度的候选清单
node docs/review/tools/coverage-detail.mjs [buffId前缀] # 候选 + 当前 effects 并排，人工判定
node docs/review/tools/show.js '<buffId>'              # 单条：原文 + effects
node docs/review/tools/diff.mjs <基线提交>              # 相对某次提交的全部效果变化
```
