## 一、系统性问题（同类错误反复出现）

### 系统性问题 1：`condition` 串位到相邻 effect 上（最严重，影响 9 条）

解析器在处理「A；B。」或「A，B」结构时，经常把 B 的前提条件挂到 A 的 effect 上，或把 A 的分句塞进 B 的 `condition.extra`。典型表现：

- 第 2 条：`moodCost`（自身消耗+0.5）被挂上了 `condition = "每个进驻在制造站的黑钢国际干员"`，而该从句其实是**生产力效果的触发主体**，与心情消耗无关。
- 第 21/22 条：`clueSpeed` 挂上了 `condition = "当与萨尔贡干员进驻…"`（那是心情消耗的条件），`moodCost` 反过来挂上了 `condition = "每有1名米诺斯干员"`（那是线索速度的条件）——**两条效果的条件完全对调**。
- 第 23/24 条：`clueSpeed`（伊内丝在会客室时生效）的 `condition` 却是"当赫德雷入驻贸易站时"，反之亦然——同样**互为颠倒**。
- 第 52/53 条：`moodRecovery` / `moodCost` 被挂上了后面 resource 分句的条件（"当自身心情处于12以下时"、"当自身心情大于12时"）。

**结论**：凡是描述里出现「；」或「，当…时」的多分句技能，`condition` 归属都需要重点复核。本批共 9 条受害（2、14、19、21、22、23、24、52、53）。其中 21/22 与 23/24、73 属于更危险的**双向对调**：两条 effect 的条件被整体互换，排班会把效果应用到完全错误的场景下。

### 系统性问题 2：「每 N 个 X」的 `per` / `perValue` / `factionId` 丢失（影响 8 条）

描述里明写「每有1名『XX』干员，则 Y+N」，结果只解析出 `value: N`，把叠加分母与阵营筛选整个丢掉，导致排班会把它算成**固定一次性 +N**而非**按人数叠加**。

受害：第 9（宿舍每有1名干员→热情值+1）、29（每有1名彩虹小队→情报储备+1）、30（每有1名乌萨斯学生自治团→乌萨斯特饮+1）、32（每有1名怪物猎人小队→木天蓼+2）、51（每个岁干员→人间烟火+5）、2、19、64。

其中第 51 条尤其离谱：`per` 被写成 `resourcePoint`（把"每个岁干员"当成资源点计数），且 `perValue` 缺失，正确应为 `per: "factionMember", factionId: "sui", perValue: 1, cap: 5`。

### 系统性问题 3：`per=resourcePoint` 与「每 N 点」的语义被处理反了（影响 4 条）

- 第 31、67、68 条：「每有20点热情值」被做成 `condition: {type:"trigger"}` —— 语义变成"满足条件就固定 +X"，**丢失了"每20点跳一档"的叠加语义**。正确做法是 `per: "resourcePoint", perValue: 20`，不进 condition。
- 第 28 条（重岳）反过来：**把阈值 20 直接写成了 `value: 20`**（应为 `value: 0.05, per: "resourcePoint", perValue: 20`），会让排班算出每小时恢复 +20 心情这种荒谬结果。这是典型的"阈值当增益量"错误。

### 系统性问题 4：「反之 / 否则」分支处理错乱（2 条）

- 第 25 条（歌蕾蒂娅）：原文「反之则自身心情每小时恢复+0.5，如果…满心情，则额外+0.5」，应得 2 条不同条件的 `moodRecovery`（无条件基础 +0.5 / 满心情额外 +0.5）。实得**两条完全相同**的 effect（都带"满心情"条件），既重复又把基础恢复错误地设成必须满心情才生效。
- 第 28 条：同一条 `value: 0.05` 的 `otherFacilities` 恢复被**重复输出了两次**（第 1 条与第 3 条完全一致），中间夹着那条 value=20 的错误项。

### 系统性问题 5：`target` 精度丢失（4 条）

- 「每个进驻在制造站的XX干员生产力+X%」应为 `allManufacture`，实为 `room`（第 2 条）。同批第 69 条（薇薇安娜·骑士）与第 67/68 条都正确用了 `allManufacture`，说明是漏判而非约定如此。
- `hireSpeed` 的 target 在 `hire` 与 `room` 之间不统一：第 16 条用 `hire`，第 17/18 条用 `room`（第 17 条已是 target 语义偏差，应为 `hire`）。
- 「会客室」类效果同理：`clueSpeed` 应统一为 `meeting`，第 19 条用了 `room`。

### 系统性问题 6：`manualReview` 承担了本应解析的主效果（3 条）

第 26、27、63 条的 `manualReview.segments` 装的是「深海猎人干员获得特殊加成」「控制中枢内部分技能可以为其他设施内干员额外提供心情恢复」这类**真正的主效果表述**，而按 schema 约定 manualReview 只应放无法归类的补充从句。虽然这些技能也同时产出了 `specialBonus` effect，但 `specialBonus` 缺少阵营/范围限定（第 63 条连 `factionId` 都没有），排班无法据其计算。
