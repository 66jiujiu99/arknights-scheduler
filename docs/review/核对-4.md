## 一、系统性问题（同类错误反复出现）

### 问题 1：分段描述中「当 X 时」的 condition 被错挂到**基础效果**上（8 条）
句式「进驻贸易站时，效率+25%；当 X 时，效率额外+5%」被解析成**两条都带 condition**，基础那条（+25%/+30%）本应无条件，却被挂上了后半句的条件。
涉及：`trade_ord_spd_ext[000]`、`[001]`、`[020]`、`[021]`、`trade_ord_spd_par[000]`、`trade_ord_spd&limit_tag[000]`、`trade_ord_spd&limit&bd[000]`、`trade_ord_spd&multiPar[100]`。
反向的同类问题：`trade_ord_spd&par[001]`（维娜·维多利亚）则相反——额外那条 **漏了** condition，变成无条件生效。

### 问题 2：「高品质贵金属订单出现概率」完全没有结构化（8 条）
`trade_ord_wt&cost[000/001/002/003/004]`（小幅提升）与 `[010/011/012]`（提升）共 8 条，effects 只解析出「心情每小时消耗-0.25」，前半句的概率提升效果只进了 `manualReview`（reason: 未识别的表述），effects 条数（1）< 原文机制数（2）。
schema 里有 `orderQuality` 类型但全库 **0 条使用**；定性档位可用 `level: small/normal` 表达（对照 `control_clue_cost[000/010]` 的 level 用法）。

### 问题 3：「除自身以外每名干员」漏 `excludeSelf`（3 条）
`trade_ord_spd&share[000/001/002]`（火哨、吉星）用 `per=operator` 但**没有 `excludeSelf: true`**，会把技能持有者自己也计入，多算一份。全库 35 条 `excludeSelf` 全部集中在宿舍类技能，贸易站这类「除自身以外」句式没有套用。

### 问题 4：「每 N 个 X」的 per 挂错 / 丢失 / 错位（5 条）
- `trade_ord_spd_variable2[000/001]`（雪雉）：分母是「每 5% 效率」，应为 `per=efficiency + perValue=5`，实为 `per=operator`；且被拆成两条 `value=5`，第二条会重复计一次 +5%，应合并为一条（`value 5, per=efficiency, perValue 5, cap 25/35`）。
- `trade_ord_spd_variable3[000]`（锏）：「每 5 个订单上限」被错解析成一条独立的 `orderLimit +5` 效果，会真的加 5 个订单上限；主体应为 `orderEfficiency/percent/value=25`。
- `trade_ord_spd&meet[000/010]`（伺夜、渡桥）：「会客室每级」缺 `per=roomLevel`，变成无条件 +5%（对照 `trade_ord_spd&dorm&lv[000]`「每间宿舍每级」是正确带了 `per=roomLevel` 的）。

### 问题 5：加工站心情消耗的类型/单位混淆（1 条）
`workshop_formula_cost[010]`（年）用 `type=moodCost + unit=perHour`，会被当成「每小时心情消耗+2」；加工站按配方结算的心情应使用 `type=workshopMoodCost + unit=mood`（全库 31 条 workshopMoodCost 均如此，此条是唯一的 `moodCost@WORKSHOP`）。

### 补充建议（不计为错误）
条件中的**人物名没有抽成 `char` 字段**：`trade_ord_spd&cost_P[000]`（拉普兰德）、`trade_ord_spd_ext[*]`（乌尔比安/伺夜）、`trade_ord_spd&multiPar[100]`（能天使）等都用 `condition.type="other"` 只存了整句 text，而全库已有 `withCharInRoom` / `charInRoom` + `char` 的规范写法，建议统一，否则程序无法判断「谁在同一个贸易站」。
