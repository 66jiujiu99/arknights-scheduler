## 系统性问题

### 1. 【错误·2 条】「加工原始心情消耗为 N 的 X 材料」的阈值 N 完全丢失，且被塞进 manualReview 当补充从句

- `workshop_formula_rub[000]`（休谟斯·省省能更多）：原文「加工原始心情消耗为**2**的精英材料时，副产品概率+40%」
- `workshop_proc_cost[000]`（罗小黑·御灵之力·金）：原文「加工原始心情消耗为**8**的任意类材料时，副产品概率+50%」

两条的 effects 里 value 取对了（40 / 50），但**"原始心情消耗为 2 / 8"这个配方筛选前提既没进 condition，也没进任何字段**——
解析器把它整段丢进了 `manualReview.segments`（"未识别的表述"），等于排班时该技能会对**所有**配方生效，而原文只对心情消耗为 2 / 8 的配方生效。
解析器**已有现成字段可用**：`workshopMoodCost` 类用的是 `recipeMoodCostAtLeast`（全库 13+ 条在用，如麦哲伦「心情消耗为4以上的配方全部-2」= `recipeMoodCostAtLeast:4`），
以及 `CONDITION_RULES` 里的 `{ type:'recipeMoodCost', threshold:N }`。这两条应挂上 `condition: { type:'recipeMoodCost', threshold: 2 / 8 }`，并清空 manualReview。
同批 workshop_proc_probability 系列（无消耗阈值）不受影响，说明是**阈值句式的漏解析**，不是概率类整体问题。

### 2. 【建议·非错误】`condition.type` 大量使用 `trigger` / `other` 兜底，语义偏弱

`dorm_rec_all&tired[000]`（心情18以下额外+0.1）、`dorm_rec_all&tired[100]`（心情20以下额外+0.1）、`dorm_rec_all&bd[000]`（每有5点无声共鸣）、
`dorm_rec_all&group[000]`、`dorm_rec_all&profession[000]` 等的 condition 是 `{type:'trigger'/'other', numbers:[N]}`，靠 `text` 原文 + `numbers` 兜底。
数值与叠加量**都对**，但 `type` 没落成 `selfMoodBelow` / `resourceAtLeast` / `factionMember` 这类可计算类型，排班不能直接按条件分支。
与已核对过的 `dorm_rec_all&single[000]`（正确用了 `targetMoodNotFull`）对比，说明规则覆盖不全。**判定为"存疑"而非"错误"**，因数值本身无误、原文可由 text 复原。

### 3. 【提示·非错误】宿舍「每名 X 干员」类：触发主体未落到筛选字段

- `dorm_rec_all&profession[000]`（纯烬艾雅法拉）：「每名**行医**干员 +0.06，最多4名」→ 只有 `per:'operator'` + `cap:4`，
  **没有 `profession:'行医'`**，而 schema 里 `profession` 是明确字段（对比 `train_spd&profession3[181]` 用了 `profession:'医疗'`）。
  `行医` 是**分支(branch)**不是八职业之一，能否直接用 profession 存疑，故判"存疑"，但当前确实无法区分触发主体。
- `dorm_rec_all&group[000]`（余）：「每名**岁**干员」→ `per:'factionMember'` + `factionId:'sui'` **已正确挂上**，这条没问题。

### 4. 【提示·非错误】`per` 缺失：宿舍「每级」「每有1间发电站」的叠加单位没记

- `dorm_rec_all&lv[100]`（响石·死前必做清单）第二条：「当前宿舍**每级**为恢复效果额外+0.02」→ **缺 `per:'roomLevel'`**；
  全库同类（空弦「每间宿舍每级+1%」、锡人「每间宿舍每级+1%联络速度」）都正确带了 `per:'roomLevel'`。
- `dorm_powToRecAll[000]/[010]`（流明）：「**每有1间发电站**，恢复效果额外+0.05」→ **缺 `per:'powerStation'`**（该值在 schema 的 per 取值表内）。
  同时这两条的 condition（`{type:'other', text:'同时每有1间发电站'}`）被**同时挂到了第一条基础效果上**——原文的"每有1间发电站"只修饰 +0.05 那条，
  不修饰 +0.1 / +0.15 的基础恢复，属于 condition 挂串（同类串挂见 `dorm_rec_all&unfull[001]`、`dorm_rec_all&tag[000]`、`workshop_proc_probability&ext[001]`、`dorm_rec_oneself2[000]`）。
  数值与 stacking 均正确，故判"存疑"。

> 说明：`workshop_proc_probability` 系列的 `product:"任意类材料"` 与 `unit:"percent"` **符合本项目约定**
> （解析器 `detectProduct` 对 WORKSHOP 且 targets≥4 时统一返回"任意类材料"；`workshopByproduct` 约定 unit=percent），
> 未因提示词中"unit 应为 probability"的字面差异而判错。本批**没有**出现 workshopMoodCost 误写 perHour 的情况（该类不在本批清单内）。
